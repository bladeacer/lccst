# LCCST Playground

This directory contains the clean-room benchmark harness for LCCST. The
harness compares two implementation variants for each of three subprojects.

## Vocabulary

Use these terms with the following meanings:

- A **benchmark workspace** is a directory named
  `<provider>-<harness>-<model>`.
- A **subproject** is `python-http-server`, `react-timer`, or `go-login-crud`.
- A **plain variant** is the smallest implementation that meets the target
  specification. It does not apply `SKILL.md`.
- A **skill-guided variant** applies `SKILL.md` and the project constraints in
  `guide.md`.
- An **agent tag** is the name of the benchmark workspace directory.
- A **target specification** defines the required behaviour and file layout
  for a subproject.
- A **target path** is a filesystem path used by a benchmark command.
- A **report** is the versioned Markdown file generated by `run_benchmark.py`.

A variant is not the same as an LCCST `mode`. A variant is `plain` or
`skill-guided`. A mode is `strict` or `lean`.

## Subprojects

### Python HTTP Server

The plain variant is a single-file HTTP server with user create, read, update,
and delete (CRUD) operations. The skill-guided variant adds input validation,
an email regular expression, rate throttling, type hints, and a
`pyproject.toml` manifest.

The benchmark harness runs the skill-guided tests with this command:

```bash
uv run python3 -m pytest tests/ -v --tb=short
```

The harness sets `DISABLE_RATE_LIMIT=1` for this test run. The harness does not
run plain-variant tests.

### React Timer

The plain variant is an HTML and JavaScript stopwatch without a framework. The
skill-guided variant uses TypeScript and React. It contains a `Timer` class, a
`TimerDisplay` component, and a `formatTime()` utility.

The benchmark scanner reads `skill-guided/src/*.tsx` and
`skill-guided/tests/*.tsx`. Use the `.tsx` extension for every skill-guided
source and test file, including utility files without JSX.

The benchmark harness runs the skill-guided tests with this command:

```bash
npx --no-install jest --no-coverage
```

The harness does not run plain-variant tests.

### Go Login CRUD

The plain variant is one `main.go` file with SHA-256 password hashing and an
in-memory store. The skill-guided variant uses model, repository, handler,
middleware, and cache layers. It uses interfaces and dependency injection.

The benchmark harness runs the skill-guided tests with this command:

```bash
go test ./tests/ -v
```

The Go module uses only the standard library. The harness does not run
plain-variant tests.

## Environment

Use these host prerequisites for local benchmark work:

| Tool | Minimum version | Use |
| --- | --- | --- |
| Node.js | 18 | Run the LCCST MCP server and React projects |
| pnpm | 9 | Install Node dependencies |
| TypeScript | 5.4 | Compile the LCCST source |
| Python | 3.10 | Run the benchmark script |
| Go | 1.21 | Run the Go project |
| `uv` | 0.4 | Manage Python dependencies |

A clean-room run uses these pinned or supplied tools:

- The run uses Go 1.26.4-X with `nodwarf5`.
- The run uses Python 3.13.11.
- The run uses Node.js 18 or later.
- The run uses pnpm 11.3.0 or later.
- The environment supplies pre-cached TypeScript type definitions.

## Setup

Install the `headroom` MCP server. Follow the setup instructions at the
[headroom repository](https://github.com/chopratejas/headroom). Headroom reduces
token use while it preserves context.

Install the benchmark Python dependencies once:

```bash
cd playground/benchmarks
uv sync
cd ../..
```

`uv sync` installs `tiktoken` for the token count. The benchmark script uses a
heuristic token estimate when `tiktoken` is not available.

## Running the Benchmark

Run the harness from the repository root:

```bash
python3 playground/benchmarks/run_benchmark.py <agent-tag> [--install-deps]
```

The `<agent-tag>` value must match the benchmark workspace directory name. For
example:

```bash
python3 playground/benchmarks/run_benchmark.py \
  opencode-zen-opencode-hy3-free --install-deps
```

The `--install-deps` option runs `pnpm install` in
`react-timer/skill-guided/` when that directory has a `package.json` and no
`node_modules` directory. The option does not install global packages.

The React test command uses `npx --no-install`. The command finds Jest in the
local `node_modules/.bin` directory. Do not install Jest globally.

### pnpm build approval

pnpm 11 can block dependency build scripts. If the React install fails because
of `unrs-resolver`, approve that package before the test run. Use one of these
methods:

- Add `allow-builds=unrs-resolver` to the project `.npmrc` file.
- Add `unrs-resolver` to `onlyBuiltDependencies` in the workspace
  `pnpm-workspace.yaml` file.
- Run `pnpm approve-builds` in the project directory.

After approval, run `pnpm install --no-frozen-lockfile` in the project that
requires approval.

## What Gets Measured

The report records the following metrics:

| Metric | Meaning |
| --- | --- |
| File count | Number of source files matched by the scanner |
| Lines of code | Source lines, including blank lines and comments |
| Characters | Number of characters in the source files |
| Tokens | `tiktoken` count or the heuristic fallback count |
| Robustness score | Normalised score from tests and detected features |
| Features | Typing, security patterns, error handling, and test assertions |
| Test result | Pass or fail, exit code, `stdout`, and `stderr` |
| Tool versions | Python, pnpm, and Go versions at report time |

File count and line count do not increase the robustness score. The scanner
adds no points for extra lines or files.

### Robustness score

The score has two parts for each skill-guided subproject:

- Test execution contributes 50 points. A passing test run receives 50 points.
  A failing test run receives 15 points. A missing test tool receives 5 points.
- Feature detection contributes up to 50 points. The runner adds 17 points when
  it detects typing. It adds 17 points for detected security patterns and 16
  for detected error handling when the subproject profile includes those
  criteria.

The runner normalises each score to 100. The React profile has no security or
error-handling points. Do not add unrelated security code to the React project
to increase its score.

## Reproducing Benchmarks

### Create the workspace

Create this directory structure for the agent tag:

```text
playground/<agent-tag>/
  python-http-server/
    plain/
    skill-guided/
  react-timer/
    plain/
    skill-guided/
  go-login-crud/
    plain/
    skill-guided/
```

### Generate the plain variant

Do not load `SKILL.md` for the plain variant. Implement the smallest working
program that meets the subproject target specification. Do not add tests or
extra layers unless the target specification requires them.

### Generate the skill-guided variant

Load `SKILL.md` and `guide.md`. Follow the structure, manifests, type
boundaries, and test requirements in `guide.md`. Put source and test files in
the scanner paths.

### Install dependencies

Run these commands in each subproject's `skill-guided/` directory:

- Python: Run `uv sync`.
- React: Run `pnpm install`.
- Go: Run `go mod tidy`.

The Go project has no external dependencies. The React project needs a local
Jest installation. Approve `unrs-resolver` when pnpm requests build approval.

### Run and read the report

Run the harness with the same agent tag:

```bash
python3 playground/benchmarks/run_benchmark.py <agent-tag> --install-deps
```

Read the versioned report at:

```text
playground/benchmarks/<agent-tag>/benchmark-report-v<skill-version>.md
```

The report filename records the `SKILL.md` version used for the run.

## Adding New Agents

1. Choose an agent tag with the form `<provider>-<harness>-<model>`.
2. Create the six variant directories described in the reproduction section.
3. Generate both variants for each of the three subprojects.
4. Run the benchmark command with the exact agent tag.
5. Compare the new report with reports from other agents.

## Prerequisites

Install these tools before a local benchmark run:

- Install Python 3.10 or later.
- Install Go 1.21 or later.
- Install Node.js 18 or later.
- Install pnpm 9 or later.
- Install `uv` 0.4 or later.
- Install `tiktoken` with `uv sync` in `playground/benchmarks/`.
- Install `pytest` with `uv sync` in the Python `skill-guided/` project.
